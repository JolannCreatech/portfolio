Project Rules

This repository contains Jolann Narcisse’s personal portfolio.

Source of truth

* Read [DESIGN_BRIEF.md](./DESIGN_BRIEF.md) before implementing or changing the website’s overall design or architecture.
* Treat the brief as the primary source of truth for the visual direction and intended behaviour.
* Inspect the actual repository before making assumptions about paths, assets or existing files.

Protect source material

* Preserve original assets in content/.
* Do not delete, rename or move source files merely to simplify the website.
* Build the new implementation inside Website/, unless the repository requires a different arrangement that has been explicitly justified.
* Do not overwrite the owner’s CV, photographs, videos or project source material.

Implementation principles

* Prefer maintainable HTML, CSS and JavaScript.
* Do not introduce a framework or dependency without a concrete reason.
* Prioritise the comic-book visual identity, page composition and narrative experience.
* Do not replace the design brief with a generic portfolio template.
* Never invent personal information, project details, achievements or results.
* Make the site usable on desktop and mobile.
* Respect accessibility and reduced-motion preferences.

Working method

* Work in stages instead of implementing the entire website blindly in one pass.
* Inspect the available browser-testing tools before deciding how to verify the result.
* Do not claim visual testing was completed unless the pages were actually rendered and inspected.
* Run relevant checks after implementation and fix discovered problems.
* Preserve working parts of the new implementation when making later revisions.
* Avoid rewriting unrelated files.

Completion reports

Clearly distinguish between:

* Work completed.
* Checks actually performed.
* Problems discovered and fixed.
* Checks that could not be performed.
* Remaining placeholders or limitations.
